# LINE Seed 字型資產

全站字型統一為 **LINE Seed**（LY Corporation，SIL Open Font License 1.1）。
`public/fonts/` 底下的所有檔案都是 `build.py` 產生的，**不要手動編輯**。

```bash
python3 scripts/fonts/build.py         # 產生（來源字型會自動下載到 .src/）
python3 scripts/fonts/build.py --ui    # 只重新拆分介面層的前台／其他（見下面「介面層拆成兩份」）
python3 scripts/fonts/verify.py        # 驗證產出並量測下載成本
```

需要 `python3`（含 `fonttools`、`brotli`）與 `npx`。產物已進版控，
所以一般開發與 Amplify 部署都不需要跑這兩支腳本。

## 為什麼換掉原本的字型

舊的字型堆疊是 `'Nanum Pen Script', 'JasonHandwriting2', sans-serif`。
Nanum Pen Script 是韓文手寫體，但**內含 435 個漢字**（韓文漢字），排在第一順位，
所以一句中文會被拆成兩套字型渲染。實測一句 36 字的應援留言：

```
我愛最的好加生日福體                      ← 10 字來自 Nanum Pen Script
你們棒演唱會聽油謝謝快樂祝永遠支持喜歡哥哥姐姐團專輯  ← 26 字來自 JasonHandwriting2
```

在 LED 牆放大 15 秒時，字重與字寬不一致會很明顯。LINE Seed TW 單一字型就涵蓋
中英數，不需要 fallback 鏈，順帶修掉這個問題。

另外 `body` 原本指定 `'Noto Sans TC'` 但全站沒有任何地方載入它，是無效宣告。

## 三層設計

這個專案的用字行為有一個關鍵特性：**使用者的便利貼內容永遠是 Regular**
（`TextBlockInstance` 只有 `color` / `align`，編輯器沒有粗體選項），
**粗體只出現在 App 自己的介面文字上**，而介面文字在編譯時就是固定的。

| 層 | 內容 | 字重 | 載入方式 |
|---|---|---|---|
| 介面 | 掃描原始碼得到的字 + 拉丁 + 標點，共 1,058 個碼位 | 400 / 700 / 800 | @font-face 內嵌在 `<head>`，woff2 分三份預載（見下面「介面層分三份」） |
| 中文內容 | LINE Seed TW 扣掉介面字集，12,860 字 | 700 | 693 個 unicode-range 分片 |
| 韓文內容 | LINE Seed Sans KR，只保留韓文 | 700 | 169 個 unicode-range 分片 |

（2026-11-01 完整重建後的數字。）

介面字集用「掃描整個 `app/` 與 `server/` 的 CJK 字元」取得，字串常數（例如 `showAlert()`
的訊息）都會被掃到。註解不算：原本連註解一起掃，2026-10 量到字集有三分之一以上只出現在註解裡，
三個字重的介面字型各從 286 KB 縮到 190 KB。萬一有字被誤判成註解，那個字會改由內容分片
（只有 700）供應：不會變豆腐，但在 400 的文字裡會單獨粗一個字，看到時把那段文字的寫法查一下。

### 介面層分三份

每個字重依「多早需要」拆成三個檔案（2026-11 起）：

| 檔案 | 收哪些字 | 大小（每個字重） | 載入時機 |
|---|---|---|---|
| `line-seed-ui-{400,700,800}.woff2` | 首頁開場的字 + 拉丁 + 標點 | 約 38 KB | 每一頁都預載（`nuxt.config.ts`） |
| `line-seed-ui-front-{400,700,800}.woff2` | 其他前台頁面（編輯器、我的便利貼）的字 | 約 120 KB | 首頁以外的頁面預載（`app.vue`）；首頁等 START 能按之後才抓 |
| `line-seed-ui-more-{400,700,800}.woff2` | 只出現在後台、LED 牆、條款與隱私權頁的字 | 約 49 KB | 畫到那些字才下載 |

原本只有一份、每個字重約 195 KB，首頁一進來就要先下載三個字重共 585 KB，現在是 115 KB。
怎麼分由 `build.py` 的 `UI_HOME_SOURCES`、`UI_SECONDARY_SOURCES` 決定（列出檔案的路徑），
檔名與預載集中在 `app/utils/ui-fonts.ts`。列錯只影響快慢、不影響顯示：每個字都一定在其中一份裡，
晚一點下載的那幾個字會先用系統字、載完再換。**首頁多了新的元件或翻譯檔，記得加進 `UI_HOME_SOURCES`**，
不然開場會有幾個字閃一下。

- 首頁開場那份以外的字裡，有不少便利貼常用字（快、樂、希望、唱、年、月）。
  便利貼的字一律是 700，所以 `plugins/content-font.client.ts` 會提前抓 `-front-700` 與 `-more-700`，
  之後才出現的字（使用者打的、晚一點進來的便利貼）才不會閃一下。時間點是頁面資源都下載完之後：
  畫面上已經用到的字瀏覽器本來就會自己載，太早抓會跟編輯器開場的圖片搶頻寬（實測 START 晚約 0.3 秒）。
- 在瀏覽器端提前抓字型要用 `loadUiFontNow`（`app/utils/ui-fonts.ts`），**不要動態加 `<link rel="preload">`**：
  實測 Chrome 不會把那種 preload 配給 @font-face，字真的要用時又抓一次。HTML 裡一開始就有的 preload 沒有這個問題。
- `--ui` 只重新分配這三份，**涵蓋的字不變**（以目前的 `line-seed-ui.css` 為準），
  所以內容分片不用動。改了 `UI_SECONDARY_SOURCES`、或前台文案大改之後跑它。
  程式裡新出現、介面層還沒收的字，它會列出來（那些字目前由內容分片供應）；
  要收進介面層得跑完整的 `build.py`，近七百個內容分片會整批換掉。

TW 與 KR 的涵蓋範圍天然互補，合成同一個 `font-family` 後瀏覽器會逐字挑選來源：

| | 拉丁 | 漢字 | 韓文音節 |
|---|---|---|---|
| LINE Seed TW | 95 / 95 | 13,094 | **0** |
| LINE Seed Sans KR | 95 / 95 | **0** | 11,172 / 11,172 |

KR 會先裁掉拉丁與標點（與 TW 重疊的 568 個碼位），確保兩層的 unicode-range
完全不重疊，否則瀏覽器可能為了一個拉丁字母多抓一個韓文分片。

## 語言層（日文、韓文介面）

介面有英、日、韓文之後（見專案 README「多國語系」），日文、韓文的介面字各裁一份：

| | 來源 | 字重 | 大小（每個字重） | 載入時機 |
|---|---|---|---|---|
| `line-seed-ui-ja-*.woff2` | LINE Seed JP | 400 / 700 / 800 | 約 66 KB | 介面是日文才內嵌 @font-face 並預載 |
| `line-seed-ui-ko-*.woff2` | LINE Seed Sans KR | 400 / 700 | 約 22 KB | 介面是韓文才載入 |

- **用獨立的 font-family**（`LINE Seed JP UI`、`LINE Seed KR UI`），由 `base/_global.scss` 的
  `html:lang(ja)`／`html:lang(ko)` 排在 `LINE Seed` 前面。不併進同一個 family：日文的漢字（応、気）
  TW 沒有，共用的漢字字形也是台灣的寫法；跟內容分片搶同一個字時，後宣告的會贏，會多抓分片。
- **便利貼不吃語言層**：StickyNote、NoteNameTag 明寫 `$font-sans`，不然同一張便利貼在日文介面的預覽、
  下載的圖，跟 LED 牆上看起來會不一樣。
- 字集從 `app/locales/ja`、`ko` 的字串掃出來（加上語言選單上的名稱）；這三個語言的翻譯檔**不算進**
  TW 介面字集，否則日文的漢字會塞進每個人都要預載的檔案。
- 韓文沒有 800（LINE Seed Sans KR 只有 Th／Rg／Bd），800 的大標由瀏覽器挑 700。
- **改了日文或韓文翻譯就跑 `python3 scripts/fonts/build.py --locale-ui`**（幾秒鐘，只重建這一層）。
  沒跑的話新字會退回 TW 的字型：顯示得出來，但字形不一致。
- 英文與韓文的翻譯不要用彎引號（’ “ ”）和 …：LINE Seed TW 的這幾個字是全形的，
  夾在英文裡會多出一大塊空白。用直引號和三個句點。

## 分片大小怎麼定的

每個 woff2 分片有約 4.7 KB 的固定開銷，所以分片越小、單張便利貼抓得越少，
但總量越大。實測 LINE Seed TW Regular（13,918 字）在不同 `chunkSize` 下的表現：

| chunkSize | 分片數 | 總量 | 一張中文便利貼 |
|---|---|---|---|
| 8,000 | 1,085 | 8.33 MB | **170.9 KB** |
| 20,000 | 474 | 7.36 MB | 308.4 KB |
| 80,000 | 164 | 6.71 MB | 543.2 KB |
| 150,000 | 104 | 6.43 MB | 709.7 KB |

也量過「不分片直接下整包」的交叉點：畫面上同時出現約 **1,700 個不同字**時，
分片才會輸給整包 3.27 MB。實際頁面規模都在交叉點以下：

| 畫面上的不同字 | 分片累計 | 整包 |
|---|---|---|
| 30（編輯器自己那張） | 0.18 MB | 3.27 MB |
| 300（LED 牆 16 張） | 1.33 MB | 3.27 MB |
| 1,000（首頁 100 張） | 2.43 MB | 3.27 MB |

手機的關鍵路徑是編輯器，所以取 `chunkSize = 8000`。
`--languageAreas true` 也要開，同樣條件下可以從 271 KB 降到 171 KB。

> 註：cn-font-split 的分片**順序與字頻無關**（實測最高頻字的 chunk index
> 中位數落在 1047 / 1085，反而在最後段），所以不能靠「合併尾段冷門字」
> 來省開銷。省開銷的唯一方式是介面層那個預載檔。

## 實際成本

`verify.py` 2026-11-01 的量測，以編輯器為準（首頁開場與前台兩份介面字都預載了）。
額外流量含 `line-seed-ui-more-700.woff2`（約 49 KB）：便利貼常用字有一部分在那一份裡，
實際上是頁面資源下載完之後就提前抓好的。

| | 額外檔案 | 額外流量 |
|---|---|---|
| 一張中文便利貼 | 10 個 | 85.0 KB |
| 一張韓文便利貼 | 12 個 | 48.1 KB |
| 中韓混合便利貼 | 9 個 | 81.9 KB |

預載的介面字：首頁 **114 KB**，其他前台頁面 114 + 360 = **474 KB**（拆分前每一頁都是 585 KB）。
對照改版前任何一頁只要出現中文就要下載 7.5 MB。

## 幾個容易踩到的點

- **`local()` 一定要拿掉。** cn-font-split 預設會產生 `src:local("LINE Seed"),url(...)`，
  裝了 LINE Seed Sans EN（不含漢字）的機器會優先用本機版本而變成豆腐字。
  `build.py` 的 `collect_faces()` 會移除它，`verify.py` 會檢查沒有殘留。
- **`editor.vue` 的分享／下載功能。** `buildFontEmbedCSS()` 必須只嵌入該張便利貼
  用到的字所在的分片。若改回「全部嵌入」會抓 6.6 MB 並讓手機 OOM。
- **改動介面文案之後要重跑 `build.py`。** 新增的字如果不在介面字集裡，
  會改由內容分片供應——顯示正常，只是多一次請求。`verify.py` 會把這種情況量出來。
